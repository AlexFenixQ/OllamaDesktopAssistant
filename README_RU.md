# Ollama Desktop 0.1.30

Готовое Windows-приложение для Ollama Cloud. Обычному пользователю нужен только установщик из папки release; .NET включён. Office, Git, SDK и локальная Ollama не требуются.

## Интерфейс

Слева — новый чат, поиск по сообщениям, раскрываемые проекты и история. Панель сворачивается; файлы открываются кнопкой справа вверху. Основная тема тёмная, светлая доступна в настройках. Enter отправляет запрос, Shift+Enter вставляет новую строку, Ctrl+Enter также отправляет. Кнопка остановки прерывает текущую операцию. Созданные файлы можно открыть, сохранить как или показать в папке.

Проекты сохраняют существующие инструкции и ручные заметки памяти. Меню ⋯ проекта позволяет переименовать его или удалить с подтверждением: чаты и файлы при этом остаются в общей истории. Меню ⋯ чата позволяет выбрать проект для переноса. Общие файлы проектов и автоматическая память между чатами в этот выпуск не входят.

## Обновление установленной 0.1.29

Закройте приложение и запустите готовый Update.ps1 через Windows PowerShell. Он проверяет пакет, подпись релиза и файлы старой версии. Затем без окон установщика создаёт проверенные резервные копии программы и всего каталога Data, устанавливает новую версию, проверяет её и запускает приложение. Неизвестная или изменённая установка отклоняется. При сбое после начала установки выполняется восстановление файлов приложения; пользовательский Data не заменяется.

Чистая установка: release\OllamaDesktop-0.1.30-win-x64-Setup.exe. Существующую установку обновляйте через Update.ps1, а не прямым запуском установщика.

## Обновления из приложения

«Обновления» позволяет выбрать стабильный или бета-канал. По умолчанию включён стабильный канал и проверка при запуске/раз в 6 часов. Бета включает стабильные выпуски и версии вида 0.2.0-beta.1. Понижение версии автоматически не выполняется. Ошибка сети не мешает работе с историей и не начинает установку.

Приложение предлагает новый выпуск. Только после нажатия «Обновить и перезапустить» скачивает файлы, проверяет RSA/SHA-256 подпись и хеши, ждёт окончания текущей операции, сохраняет черновик с подготовленными вложениями и запускает скрытое обновление. Скачивание и ожидание можно отменить. Установщик не показывает мастера или прогресс-окна; компьютер не перезагружается. Обновление доступно установленной версии в стандартной папке, а не произвольной тестовой сборке.

Источником служит https://github.com/AlexFenixQ/OllamaDesktopAssistant/releases . Обновления принимаются только из этого репозитория, с версией/каналом/минимальной базой, подтверждёнными закреплённым открытым ключом приложения. Закрытый ключ подписи не входит в исходники и защищён DPAPI у владельца. RSA-подпись манифеста не является сертификатом Authenticode установщика: сертификат издателя в этот выпуск не включён.

## Данные и откат

Данные находятся отдельно: %LOCALAPPDATA%\OllamaDesktopAssistant\Data. Ключ — в key.dpapi, зашифрован DPAPI текущей учётной записи Windows. История, проекты, вложения и созданные файлы не публикуются. Для облачных запросов выбранные материалы передаются Ollama; обновления не отправляют историю или ключ в GitHub.

Резервные копии тихого обновления: %LOCALAPPDATA%\OllamaDesktopAssistant\Backups\Update-*. Последняя транзакция: last-update.json рядом с Data. Для ручного отката закройте приложение и запустите scripts\Rollback-SilentUpdate.ps1: сценарий сам найдёт последнюю резервную копию, проверит файлы и попросит локально ввести ДА. Пользовательский Data, включая новые чаты после обновления, не заменяется резервной копией. Резервные копии содержат частные данные — не публикуйте их.

## Сборка владельцем

Windows x64, Windows PowerShell 5.1: Start.ps1 проверяет MANIFEST, готовит официальный .NET 10 SDK и Inno Setup, собирает self-contained приложение и исполняет тесты. Зависимости закреплены packages.lock.json. scripts\Build.ps1 — сборка и тесты; scripts\Test.ps1 — повтор тестов; scripts\Package.ps1 — установщик. Для подписи обновлений предусмотрен scripts\Sign-Update.ps1 с параметром PrivateKeyPath: секрет не вводится в командную строку, передаётся только путь к DPAPI-файлу владельца. Существующий ключ сохраняется вне каталога исходников; новый произвольный ключ не подойдёт уже установленным клиентам.

## Статус проверок

Фактические результаты находятся в TEST_STATUS.json и verification. Проверки на отдельном чистом компьютере без среды разработки отмечаются отдельно; непроведённые проверки не считаются пройденными. Предварительный просмотр --preview использует только синтетические данные во временной папке и не читает реальную историю или ключ.
